Pratique : décoder des trames avec Python

Lire un DBC, encoder et décoder, simuler un bus, rejouer un enregistrement. Sans matériel.

Exemples fictifs. Faites défiler avec les flèches du clavier, le balayage ou les boutons.

Ce qu’on va faire

Un bus virtuel remplace le matériel : un émetteur et un récepteur échangent de vraies trames, dans le même programme.

Installation

mkdir pratique-can && cd pratique-can
python3 -m venv venv
source venv/bin/activate
pip install python-can cantools
  • cantools : lit les fichiers DBC, encode et décode les messages.
  • python-can : envoie et reçoit des trames, sur un vrai bus ou un bus virtuel.

Windows : activer l’environnement avec venv\Scripts\activate.

Le fichier DBC fictif

BU_: ECU_A ECU_B

BO_ 672 VehicleSpeed: 2 ECU_A
 SG_ Speed : 0|16@1+ (0.1,0) [0|250] "km/h" ECU_B

BO_ 448 EngineData: 2 ECU_A
 SG_ CoolantTemp : 0|8@1+ (1,-40) [-40|215] "degC" ECU_B
 SG_ Gear : 12|4@1+ (1,0) [0|15] "" ECU_B

BO_ 1024 SpeedMotorola: 2 ECU_A
 SG_ SpeedM : 7|16@0+ (0.1,0) [0|250] "km/h" ECU_B

VAL_ 448 Gear 0 "Neutre" 1 "Premiere" 3 "Troisieme" ;

Extrait : le fichier complet (avec l’en-tête VERSION, NS_, BS_) est dans le texte du module.

Décoder un message

import cantools
db = cantools.database.load_file("exemple.dbc")

print(db.decode_message(0x2A0, bytes([0xE8, 0x03])))
print(db.decode_message(0x1C0, bytes([0x7B, 0x30])))
print(db.decode_message(0x1C0, bytes([0x7B, 0x30]),
                        decode_choices=False))
{'Speed': 100.0}
{'CoolantTemp': 83, 'Gear': 'Troisieme'}
{'CoolantTemp': 83, 'Gear': 3}

Encoder, et Intel contre Motorola

print(db.encode_message("VehicleSpeed", {"Speed": 100.0}).hex(" "))
print(db.encode_message("SpeedMotorola", {"SpeedM": 100.0}).hex(" "))
e8 03
03 e8

Même vitesse de 100 km/h : les octets sont inversés selon l’ordre déclaré dans le DBC.

Un bus virtuel

emetteur  = can.Bus(interface="virtual", channel="demo")
recepteur = can.Bus(interface="virtual", channel="demo")
emetteur.send(can.Message(arbitration_id=0x2A0, data=data,
                          is_extended_id=False))
msg = recepteur.recv(timeout=0.5)

Résultat sur le bus virtuel

0x2A0 e8 03 -> {'Speed': 100.0}
0x1C0 7b 30 -> {'CoolantTemp': 83, 'Gear': 'Troisieme'}
0x2A0 b5 04 -> {'Speed': 120.5}
0x1C0 7d 30 -> {'CoolantTemp': 85, 'Gear': 'Troisieme'}

Vérification à la main : 120,5 km/h → valeur brute 1205 = 0x04B5 → en Intel : b5 04.

Rejouer un enregistrement

(1700000000.000000) vcan0 2A0#E803
(1700000000.010000) vcan0 1C0#7B30
(1700000000.100000) vcan0 2A0#D007
(1700000000.110000) vcan0 1C0#3C10
for msg in can.LogReader("trace.log"):
    print(db.decode_message(msg.arbitration_id, msg.data))
{'Speed': 100.0}   {'CoolantTemp': 83, 'Gear': 'Troisieme'}
{'Speed': 200.0}   {'CoolantTemp': 20, 'Gear': 'Premiere'}

À retenir

  • cantools encode et décode avec un DBC ; python-can envoie et reçoit des trames.
  • Le bus virtuel permet de s’exercer sans matériel.
  • Intel et Motorola donnent des octets différents pour une même valeur.
  • Un enregistrement se rejoue avec LogReader.
  • Sur du vrai matériel : écouter d’abord, n’émettre que sur un banc d’essai, jamais sur un véhicule roulant.

Prochain parcours : architecture et diagnostic (UDS, AUTOSAR, ISO 26262).
